## HIGH

### H-01 Event Listener Memory Leak ✅ FIXED
**File:** `packages/runtime-player/src/sim/simPlayer.ts`

`clickLayerEl.addEventListener('click', onClickLayer)` was registered but the returned cleanup function only called `cancel()` (cancels the demo timer). The click listener was never removed, causing a memory leak every time a slide with a sim widget was navigated away from.

**Fix:** Changed cleanup to:
```typescript
return () => {
  cancel()
  clickLayerEl.removeEventListener('click', onClickLayer)
}
```
The host (`goToSlide`) calls this cleanup before replacing `container.innerHTML`, so both the timer and the listener are torn down on navigation.

### H-02 Hint Repeated on Every Wrong Attempt ✅ FIXED
**File:** `packages/runtime-player/src/sim/simPlayer.ts`

The hint text was prepended to the feedback message on every incorrect click after the first miss, not just the first time. The condition `attemptCount >= 1 && step.hint` was always true after the initial miss.

**Fix:** Added a `hintShown` boolean (reset in `loadStep()`). Hint is only prepended when `!hintShown && step.hint`, then `hintShown` is set to `true`:
```typescript
let msg = step.incorrectFeedback || 'Try again.'
if (!hintShown && step.hint) {
  msg = `${step.hint} — ${msg}`
  hintShown = true
}
showFeedback(msg, '#f39c12')
```

## MEDIUM

### M-01 Demo Delay No Upper Bound ✅ FIXED
**File:** `packages/runtime-player/src/sim/simPlayer.ts`

`step.demoDelay` was used directly without clamping. A value of `0` or a very large number could cause an instant advance (no time to see the screenshot) or an effectively infinite pause that hangs the demo.

**Fix:** Clamped to a safe range:
```typescript
const delay = Math.min(Math.max(step.demoDelay > 0 ? step.demoDelay : 1500, 100), 30_000)
```
- Minimum: 100ms (prevents instant flicker)
- Default when ≤0: 1500ms
- Maximum: 30s (prevents runaway hangs)

### M-02 Assessment Scoring Semantics Undocumented ✅ FIXED
**File:** `packages/runtime-player/src/sim/simPlayer.ts`

`correctCount / steps.length` silently scored steps where `maxAttempts` was exhausted as 0, but this was not documented. A reader could mistake it for a bug or assume exhausted steps are excluded from the denominator.

**Fix:** Added an explanatory comment:
```typescript
// score = fraction of steps where the learner clicked inside the hotspot.
// Steps where maxAttempts was exhausted without a correct click count as 0.
const score = correctCount / steps.length
```
