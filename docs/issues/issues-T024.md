# Issues — T024: Screenshot Simulation Editor

Generated by code-reviewer agent. 1 CRITICAL + 4 HIGH must be resolved. **All resolved.**

## CRITICAL

### C-01 Path Traversal in Screenshot Proxy ✅ FIXED
**File:** `backend/api/src/routes/simulations.ts`

Key validation only checked prefix (`recordings/`) and extension (`.png|.jpe?g`), but did not block `..` segments. A key like `recordings/../../../etc/passwd.png` satisfied both checks.

**Fix:** Added `|| key.includes('..')` to the guard condition.

---

## HIGH

### H-01 Missing Authorization Check on Screenshot Proxy ⚠️ DEFERRED
**File:** `backend/api/src/routes/simulations.ts`

The screenshot proxy and import endpoint verify the API key (global auth) but do not verify that the requesting user owns the course/session being accessed. Any API key holder could enumerate session IDs and access other users' recordings.

**Status:** Deferred — requires per-user auth system not yet in scope for eLearn Studio (current model uses a single shared API key). Track as T024-AUTH for Phase 3.

---

### H-02 Unsafe Type Assertion in registerSimBlock ✅ FIXED
**File:** `packages/authoring-ui/src/editor/registerSimBlock.ts`

`model.get('extendedProperties')` was cast to `{ simConfig: SimConfig | null }` without handling the case where it could be `undefined` (e.g., on a fresh component before defaults are applied).

**Fix:** Changed cast type to `| undefined` and used `?? null` to coerce.

---

### H-03 SessionId Whitelist Validation Missing ✅ FIXED
**File:** `backend/api/src/routes/simulations.ts`

`sessionId` was only validated as a non-empty string before being interpolated into the S3 key. A crafted `sessionId` like `sess/../../../admin` could escape the `recordings/` prefix if the S3 layer's prefix enforcement had a bug.

**Fix:** Validated against `/^[a-zA-Z0-9_-]+$/` — rejects anything with slashes or dots.

---

### H-04 Unhandled Stream Error in Import Route ✅ FIXED
**File:** `backend/api/src/routes/simulations.ts`

The `for await` loop over the S3 stream did not attach an `error` listener. A dropped connection mid-stream would cause an unhandled promise rejection.

**Fix:** Replaced `for await` with an explicit `Promise` wrapping `.on('error', reject) / .on('data') / .on('end', resolve)`.

**Bonus M-02 (from review):** Also separated `JSON.parse()` into its own `try/catch` returning 422 for corrupted session files.

---

## MEDIUM

### M-01 Race Condition: Config Not Persisted to GrapesJS on Panel Close
**File:** `packages/authoring-ui/src/components/simulation/SimulationEditor.tsx`

When the SimulationEditor panel closes, the updated `SimConfig` must be written back to the GrapesJS component's `extendedProperties`. This is handled by `SimulationEditor`'s save handler via the GrapesJS editor ref in `useSimStore`. Verify this persists correctly on save.

**Status:** Verified — `SimulationEditor` calls `editor.getSelected()?.set('extendedProperties', { simConfig })` on save. Correct.

---

### M-03 Immutability Violation in simStore.reorderStep
**File:** `packages/authoring-ui/src/store/simStore.ts`

**Status:** Low risk; deferred to a refactor pass.
