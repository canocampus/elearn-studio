## CRITICAL

### C-01 INI Injection via Course Title ✅ FIXED
**File:** `packages/scorm-packager/src/aicc.ts`

`buildCourseDescriptor()` interpolated `course.title` and `opts.courseSystemId` directly into INI format without sanitising newlines. A title like `"Evil\r\nCourse_ID=HACKED"` injected an extra `Course_ID=` key into the `.crs` file, which could override the legitimate value in sequential LMS parsers.

**Fix:** Added `iniValue()` helper that replaces `\r` and `\n` with a space and trims. Applied to all INI right-hand-side values in `buildCourseDescriptor`.

```typescript
function iniValue(value: string): string {
  return value.replace(/[\r\n]/g, ' ').trim()
}
```

### C-02 CSV Row Injection via Newlines in Title ✅ FIXED
**File:** `packages/scorm-packager/src/aicc.ts`

`csvField()` quoted values and escaped double-quotes but did not strip embedded CR/LF. A title containing `\r\n` split the CSV row in the `.des` file, potentially causing AICC parsers to interpret injected text as a new row.

**Fix:** Added `\r\n` sanitisation inside `csvField()` before applying RFC 4180 quoting:

```typescript
function csvField(value: string): string {
  const sanitised = value.replace(/[\r\n]/g, ' ').trim()
  return '"' + sanitised.replace(/"/g, '""') + '"'
}
```

### C-03 Unvalidated HACP Bridge Injection in buildIndexHtml ✅ FIXED
**File:** `packages/scorm-packager/src/index.ts`

The `bridge` parameter was embedded directly into `<script>` content without validation. If a caller passed a non-IIFE string, arbitrary JavaScript could execute in the player. Although `packAICC()` always derives the bridge from `buildHACPBridge()`, the public function signature accepted any string.

**Fix:** Added an IIFE structure guard in `buildIndexHtml`:

```typescript
if (bridge !== undefined && !/^\s*\(function\s*\(\s*\)/.test(bridge)) {
  throw new Error('bridge must be a valid IIFE from buildHACPBridge()')
}
```

## HIGH

### H-01 Cross-Origin AICC_URL Accepted by Bridge ✅ FIXED
**File:** `packages/scorm-packager/src/hacp-bridge.ts`

The bridge read `AICC_URL` from query params and posted SCORM data to it without origin validation. A crafted launch URL pointing at an attacker's server would exfiltrate all learner data (lesson_status, score, suspend_data).

**Fix:** Added same-origin check after reading `AICC_URL`:

```javascript
try {
  var parsedUrl = new URL(aiccUrl, location.href);
  if (parsedUrl.origin !== location.origin) {
    console.warn('[HACP] AICC_URL origin mismatch — refusing cross-origin POST:', parsedUrl.origin);
    return;
  }
} catch (e) {
  console.warn('[HACP] Invalid AICC_URL:', aiccUrl);
  return;
}
```
