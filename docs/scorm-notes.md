# SCORM/AICC Compatibility Notes

**Last Updated:** 2026-03-22

eLearn Studio generates SCORM 1.2 and AICC packages that can be deployed to any LMS. This document covers the package formats, data model, and LMS compatibility.

---

## SCORM 1.2 Package Structure

A SCORM 1.2 ZIP package contains:

```
course_title_scorm12.zip
├── imsmanifest.xml              ← Required; defines course structure
├── index.html                   ← Entry point; embeds course data
├── player.js                    ← Runtime player (compiled from packages/runtime-player)
└── assets/                      ← Optional; course media (images, audio, video, …)
    ├── slide-1-image.png
    ├── quiz-audio.mp3
    └── …
```

### imsmanifest.xml

Generated by `/packages/scorm-packager/src/index.ts`, function `buildManifest()`.

**Required sections:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<manifest identifier="ELEARN_<courseId>" version="1"
  xmlns="http://www.imsproject.org/xsd/imscp_rootv1p1p2"
  xmlns:adlcp="http://www.adlnet.org/xsd/adlcp_rootv1p2">

  <!-- Metadata -->
  <metadata>
    <schema>ADL SCORM</schema>
    <schemaversion>1.2</schemaversion>
  </metadata>

  <!-- Organization structure -->
  <organizations default="ORG_1">
    <organization identifier="ORG_1">
      <title>Course Title</title>
      <item identifier="ITEM_1" identifierref="RES_1">
        <title>Course Title</title>
        <adlcp:masteryscore>80</adlcp:masteryscore>
      </item>
    </organization>
  </organizations>

  <!-- Resource mapping -->
  <resources>
    <resource identifier="RES_1" type="webcontent" adlcp:scormtype="sco" href="index.html">
      <file href="index.html" />
      <file href="player.js" />
    </resource>
  </resources>

</manifest>
```

- `identifier`: Unique course ID (defaults to `ELEARN_<courseId>`)
- `adlcp:masteryscore`: Passing score (from `course.metadata.masteryScore` or `course.settings.passingScore`, default 80)
- All slides are bundled in a single SCO (Shareable Content Object)

### index.html

Serves as the SCO launch point. Structure:

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8" />
  <title>Course Title</title>
  <style>/* container styles */</style>
</head>
<body>
  <div id="elearn-player"></div>
  <script>
    var _courseData = { /* entire course JSON */ };
    if (typeof ELearnPlayer !== 'undefined') {
      ELearnPlayer.init('elearn-player', _courseData);
    }
  </script>
  <script src="player.js"></script>
</body>
</html>
```

**Key details:**
- Course data is embedded as a JSON object in a `<script>` tag before player.js loads
- player.js defines the global `ELearnPlayer` object
- `ELearnPlayer.init(elementId, courseData)` initializes the player
- Slide dimensions from `course.settings` (default 1024×768)

### player.js

Compiled from `/packages/runtime-player/`. It contains:

- Course rendering logic (GrapesJS-compatible HTML/CSS playback)
- Action executor (event → action dispatch)
- Question widgets and scoring engine
- SCORM API wrapper (LMS communication)
- Suspend/resume state serialization

## SCORM 1.2 Data Model (cmi.*)

The runtime player interacts with the SCORM LMS via the SCORM 1.2 API object (window.API).

### SCORM API Methods Used

```typescript
// Set a value
api.LMSSetValue(element, value): string  // Returns 'true' or 'false'

// Get a value
api.LMSGetValue(element): string  // Returns the value or error string

// Initialize communication
api.LMSInitialize(''): string  // Returns 'true'

// Finalize communication
api.LMSFinish(''): string  // Returns 'true'

// Get error info
api.LMSGetLastError(): string  // Error code
api.LMSGetErrorString(errorCode): string  // Error message
```

### cmi.* Fields Accessed

| Field | Set By | Read By | Purpose |
|---|---|---|---|
| `cmi.core.student_id` | LMS | Player | Learner identifier (read-only) |
| `cmi.core.student_name` | LMS | Player | Learner name (read-only) |
| `cmi.core.lesson_status` | Player | LMS | 'not attempted', 'incomplete', 'completed', 'passed', 'failed' |
| `cmi.core.score.raw` | Player | LMS | Raw score [0, 100] |
| `cmi.core.score.min` | — | LMS | Minimum score = 0 |
| `cmi.core.score.max` | — | LMS | Maximum score = 100 |
| `cmi.core.total_time` | Player | LMS | Total session time (ISO 8601 duration) |
| `cmi.suspend_data` | Player | Player | Serialized player state (compressed, max 4096 chars) |
| `cmi.comments` | Player | LMS | Optional learner comments |
| `cmi.launch_data` | — | Player | LMS parameters (read-only) |

### Typical Workflow

1. **Initialize:** `LMSInitialize('')` → 'true'
2. **Get student info:** `LMSGetValue('cmi.core.student_id')` → "alice@example.com"
3. **Restore suspend data:** `LMSGetValue('cmi.suspend_data')` → decompressed state
4. **Player runs** (learner answers questions)
5. **Save score:** `LMSSetValue('cmi.core.score.raw', '75')` → 'true'
6. **Save status:** `LMSSetValue('cmi.core.lesson_status', 'passed')` → 'true'
7. **Suspend state:** `LMSSetValue('cmi.suspend_data', compressed)` → 'true'
8. **Finalize:** `LMSFinish('')` → 'true'

## Suspend/Resume (cmi.suspend_data)

The suspend/resume system serializes player state into a compressed string stored in `cmi.suspend_data`.

### SuspendData Format (v:1)

Compressed (LZString) JSON:

```json
{
  "v": 1,
  "slide": 3,
  "scores": [
    ["w-q1", { "s": 1.0, "w": 100, "a": true }],
    ["w-q2", { "s": 0.5, "w": 100, "a": true }],
    ["w-q3", { "s": 0.0, "w": 100, "a": false }]
  ]
}
```

- `v`: Format version (currently 1)
- `slide`: 0-based slide index to resume from
- `scores`: Array of `[widgetId, { score, weight, answered }]` tuples
  - `s` (score): [0.0, 1.0]
  - `w` (weight): Question weight (default 100)
  - `a` (answered): Whether learner has answered

### Serialization

Done by `/packages/runtime-player/src/suspend.ts`, function `serializeSuspend()`:

1. Validate slide index (must be integer ≥ 0)
2. Extract question scores from `state.questionStates` Map
3. Serialize to JSON
4. Compress with `LZString.compressToEncodedURIComponent()`
5. Check length ≤ 4096 chars
6. Return compressed string

**Example:**
```typescript
const state: SuspendableState = {
  currentSlide: 2,
  questionStates: new Map([
    ['w-q1', { widgetId: 'w-q1', score: 0.8, weight: 100, answered: true }]
  ])
}
const compressed = serializeSuspend(state)
// Result: "LQhABgJAAAEBMCAEIJIMUAJAAAw..."
```

### Deserialization

Done by `deserializeSuspend()`:

1. Check for empty string → return null
2. Decompress with `LZString.decompressFromEncodedURIComponent()`
3. Parse JSON
4. Validate version (must be 1)
5. Validate structure (slide is number, scores is array)
6. Return payload or null

**On resume:**
```typescript
const raw = api.LMSGetValue('cmi.suspend_data')
const payload = deserializeSuspend(raw)
if (payload) {
  player.currentSlide = payload.slide
  // Restore question scores
  for (const [widgetId, q] of payload.scores) {
    player.questionStates.set(widgetId, {
      widgetId,
      score: clamp(q.s, 0, 1),     // Sanity clamp
      weight: q.w > 0 ? q.w : 100,
      answered: q.a === true
    })
  }
}
```

### Limitations

- **4096 character limit:** If compressed state exceeds this, it's not saved (warning logged)
- **Custom variables not persisted:** Only question scores are saved; set-variable state is lost
- **No nested question state:** Only top-level widget scores; no per-choice or per-attempt tracking
- **LZ compression dependency:** Decompression requires `lz-string` library (NPM)

## AICC Package Structure

AICC (Aviation Industry Computer-Based Training Committee) is an older standard. eLearn Studio generates AICC-compliant packages via `packAICC()` in `/packages/scorm-packager/src/index.ts`.

### File Structure

```
course_title_aicc.zip
├── course_title.crs              ← Course descriptor
├── course_title.au               ← Assignable Unit descriptor
├── course_title.des              ← Description descriptor
├── course_title.cst              ← Course Structure (tree)
├── imsmanifest.xml               ← Also included (not AICC but widely expected)
├── index.html                    ← Entry point with HACP bridge IIFE
├── player.js                     ← Runtime player
└── assets/                       ← Course media
```

### AICC Descriptor Files (INI Format)

#### .crs (Course Descriptor)

```ini
[Course]
Course_ID=ELEARN_abc123
Course_Title=My Course
Version=2.0
Total_AUs=1
Total_Blocks=0
Mastery_Score=80

[Course_Behavior_Settings]
Max_Normal=99

[Course_Description]
My Course
```

#### .au (Assignable Unit)

CSV format with header row:

```
[AU]
AU_ID,Max_Score,Max_Time,Mastery_Score,System_Vendor,Core_Vendor,File_Name,Launch_Parameters
AU_001,100,,80,,,index.html,
```

#### .des (Description)

```
[Description]
AU_ID,Title,Description
AU_001,"My Course","My Course"
```

#### .cst (Course Structure Tree)

```
[Course_Structure]
AU,Elective,AU_001
Block,Non-Elective,Root,AU_001
```

### HACP Bridge

AICC LMSes communicate via HTTP POST. The HACP (Hypertext Application Compatibility Protocol) bridge creates a mock SCORM API from HTTP responses.

Built by `/packages/scorm-packager/src/hacp-bridge.ts`:

```typescript
export function buildHACPBridge(): string {
  return `
(function() {
  window.API = {
    LMSInitialize: function(param) { /* HTTP POST /setvalue */ },
    LMSSetValue: function(element, value) { /* HTTP POST /setvalue */ },
    LMSGetValue: function(element) { /* HTTP POST /getvalue */ },
    /* … */
  }
})()
  `
}
```

The bridge intercepts calls to `window.API` and translates them to HTTP POST requests to the AICC LMS.

## LMS Compatibility

### Tested Platforms

**Moodle 4.x** ✅ Tested

- SCORM 1.2 packages work out-of-the-box
- Scoring and suspend/resume validated
- Tested with SCORM activity module

**AICC** ⚠️ Secondary target

- HACP bridge implementation is present but less well-tested
- Known to work with some enterprise LMSes (Saba, SuccessFactors, Cornerstone)
- HTTP POST endpoints may vary by LMS

**SCORM 2004** ⏳ Not yet implemented

- Would require changes to data model (cmi.interactions.*, xAPI bridge)
- Can be added if needed

**xAPI (Tin Can)** ⏳ Secondary target

- Not yet implemented
- Would complement SCORM for modern LMSes

### Troubleshooting LMS Integration

**Issue: Score not saving to LMS**

Check:
1. LMS responds to `LMSSetValue('cmi.core.score.raw', value)` with 'true'
2. Score is in range [0, 100]
3. Browser console has no SCORM API errors
4. LMS suspend data is enabled (some courses disable scoring)

**Issue: Resume doesn't restore progress**

Check:
1. `cmi.suspend_data` is being saved (check LMS database or logs)
2. Compressed data is under 4096 chars
3. LZ compression library is loaded (in player.js)
4. Slide count hasn't changed (if course is edited, suspended state may be invalid)

**Issue: AICC HTTP POST fails**

Check:
1. HACP bridge is injected (check `index.html` source)
2. AICC LMS accepts HTTP POST to `/setvalue` and `/getvalue` endpoints
3. CORS headers if HACP bridge runs in a different origin

## Packaging API

### SCORM 1.2

```typescript
import { packSCORM12 } from '@elearn-studio/scorm-packager'

const zipPath = await packSCORM12(
  course,               // CourseDoc
  '/tmp/scorm-output',  // output directory
  {
    playerPath: '/path/to/player.js',  // optional; defaults to sibling runtime-player dist
    assetPaths: [                      // optional extra files to include
      { localPath: '/path/to/image.png', zipPath: 'assets/image.png' }
    ],
    fileName: 'my-course.zip'  // optional; defaults to sanitized course title
  }
)
// zipPath: "/tmp/scorm-output/my-course.zip"
```

### AICC

```typescript
import { packAICC } from '@elearn-studio/scorm-packager'

const zipPath = await packAICC(
  course,
  '/tmp/aicc-output',
  {
    playerPath: '…',
    assetPaths: […],
    fileName: 'my-course-aicc.zip',
    auId: 'AU_001',                    // optional; default 'AU_001'
    courseSystemId: 'COURSE_ABC'       // optional; from course.metadata.identifier
  }
)
```

### Error Handling

Both functions throw errors if:
- Runtime player bundle (`player.js`) not found
- Asset file (in `assetPaths`) doesn't exist on disk
- Output directory can't be created
- ZIP archive write fails (disk full, permissions, etc.)

## Best Practices

1. **Always include assets in the package.** If images/audio are referenced as external URLs, they won't work in all LMS environments.

2. **Test in target LMS before distribution.** Even SCORM 1.2 has subtle variations in how different LMSes implement the API.

3. **Set a reasonable mastery score** in `course.metadata.masteryScore`. Default is 80, which assumes binary pass/fail. For more nuanced scoring, use question weights.

4. **Monitor suspend_data size.** Log warnings if compressed state approaches 4096 chars. If it exceeds the limit, player logs a warning and does NOT save state.

5. **Version your courses.** Use `course.metadata.version` to distinguish revisions. If you edit a course and redeploy, old suspend_data may refer to slides that no longer exist.

6. **Use standardized question types.** Custom question widgets may not score correctly if not registered with the scoring engine.
